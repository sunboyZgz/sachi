# 接入手写文章与固定 URL

## 什么时候用

已经手写了 Markdown，或正在整理目录与栏目时使用。先补齐文章身份，再保持原有 slug，避免旧链接失效。

## 开始前

手写文章位于 `content/<栏目>/<日期[-序号]>/index.md`，附件在同级 assets。目录必须符合 `2026-10-06` 或 `2026-10-06-02` 这样的格式，不能使用“手写文章”作为目录名。操作前保留自己的文件备份。

## 操作步骤

1. 进入文章信息菜单，手动输入文档路径。

2. 选择“补齐手写文章的 ID 和创建时间”，核对路径并确认。已有身份不会重建。

3. 运行检查，补齐标题等必要信息。不要把 fixture 当正式文章。

4. 首次发布前可选择修改字段里的 slug，设置可读 URL。

5. 输入字母、数字、下划线或短横线，例如 a-cup-of-tea，首字符须为字母或数字。

6. 区分身份：ID 负责稳定引用，slug 决定 /article/&lt;slug&gt;/ 地址。

### 从只有标题的 Markdown 接入

在一个未占用的日期目录中准备 index.md，至少有可解析的 frontmatter：

```markdown
---
title: 一杯茶的时间
slug: a-cup-of-tea
tags: [日常]
---

今天给自己留一点时间。

## 记录

从这里开始写。
```

不能直接把没有 `---` 的普通文本交给 `meta --init`；先按上面的结构添加元数据。选中这份文件补齐身份后，CLI 加入缺失的 UUID 与带时区创建时间；不会把 title、slug 和正文改成模板内容。然后 check，直到文章出现在正式列表中。

若要把文章换到另一栏目，把整个日期目录连同 assets、media.yaml 一起移动到目标固定栏目中，避免覆盖同名目录。保留原 id、slug、createdAt，移除与目标目录不一致的 category 字段，再检查并预览；本地移动不改变线上分类，重新选中发布后才改变。

复制一篇旧文章当新文章时，不能沿用它的 id；优先用 new 生成新身份，再粘贴正文。`meta --init` 不会覆盖已经存在的 ID，也不会自动修复重复 ID。

## 确认结果

文章有固定 UUID 与创建时间，未发布 slug 保存成功。字段见[文章契约](/reference/content)。

## 影响与取消

补齐身份不发布。移动目录不会自动改 URL，不要手动换掉已有 ID。

## 常见问题

曾发布文章即使撤回后也不能直接改 slug。阅读分钟数默认自动计算。

## 参数方式

尖括号是占位符，应换成实际文章或目录，不要原样执行。未安装简短命令时用 `npm run blog --`；已安装时可替换成 `blog`。

```sh
npm run blog -- meta content/生活旁白/2026-10-06 --init --dry-run
npm run blog -- meta content/生活旁白/2026-10-06 --init --yes
npm run blog -- meta <未发布文章> --slug a-cup-of-tea --yes
```
