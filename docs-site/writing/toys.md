# 准备玩具作品资料

## 什么时候用

准备作品名称、封面、介绍和演示视频时使用。当前完成的是本地资料登记；Yandu 尚未接入，登记成功的状态是“待媒体处理”，作品不会出现在舞台，也不会随文章发布。

## 开始前

准备真实的本地封面、演示视频以及可匿名访问的公网项目地址。视频检查需要 `ffprobe` 和 `ffmpeg`，只解码到空输出，不压缩或生成视频。可先按[运行环境检查](/start/doctor)核对工具。

原文件须为普通文件，路径各级不能是符号链接。CLI 保存引用，不复制媒体，所以原文件需要保留在原位置；仅备份 toy.yaml 不包含这些外部原文件。

## 操作步骤

### 方式一：逐项引导

1. 打开作品录入，依次填写名称、纯文字简介、封面路径、视频路径和项目地址。

   ```sh
   npm run blog -- toy add
   ```

   也可运行 `npm run blog`，选择“准备作品资料”，再选择“逐项录入作品”。输入路径以项目根目录为准，输入无效时会提示修正；最后会实际检查媒体解码和公网访问。

2. 在提交资料前，明确选择未来视频超限时的处理方式。

   ```text
   未来压缩后超过 10 MB 时如何处理？当前不上传、不裁剪。
   ❯ 超限拒绝，不裁剪
     预先同意保留开头、删除尾部
   ```

   10 MB 指 10,000,000 字节。选择允许裁剪表示未来处理时可保留开头、删除尾部；原文件不变。当前无法知道压缩后的大小或将保留多少秒，因此不会填写估算值充当结果。`--yes` 只跳过最终登记确认，不代替这个选择。

3. 选择封面铺满或完整显示，可留空视频说明。核对登记确认中的真实路径、原视频大小、时长、匿名 HTTP 结果及未来超限策略，再确认保存。

   ```text
   toy：本地资料已登记
   作品：竹影时钟
   ID：dab121ae-6c14-4bea-9e88-a2c8a0a8f525
   文件：content/toys/dab121ae-6c14-4bea-9e88-a2c8a0a8f525/toy.yaml
   状态：待媒体处理
   视频原文件：实际读取的字节数；实际读取的秒数
   未来超限策略：拒绝，不裁剪
   压缩后大小：未知；裁剪后保留秒数：未知；未来输出上限：10,000,000 字节。
   ```

   示例 ID 仅用于串联本页，复制你自己输出的完整 ID。原文件字节数和秒数来自本地媒体，不是 Yandu 处理结果。

### 方式二：生成文件后填写

1. 生成一份未登记的模板，确认后写入指定位置。已有文件不会被覆盖。

   ```sh
   npm run blog -- toy template --output ./toy.yaml
   ```

   输出模板路径，不输出作品 ID。模板的空字段必须先填写；这一步不需要媒体工具或网络。

2. 将自己的封面和视频放在模板旁的 `assets/`，填写文件。例如一份完整输入如下：

   ```yaml
   title: 竹影时钟
   description: 用竹影和光线显示时间的小工具。
   cover: ./assets/cover.png
   video: ./assets/demo.mp4
   projectUrl: https://你的公网项目域名/
   videoOverflow: reject
   coverFit: contain
   coverPosition: [50, 50]
   videoLabel: 一段实际操作演示
   ```

   将项目域名换成真实可访问地址。两个媒体相对路径以 **toy.yaml 所在目录**为准。必填前六项；后三项可省略，封面适配默认 `cover`，位置默认 `[50, 50]`。位置范围是 0–100，不能越界。没有序号字段；任何 `order`、未知字段、重复 YAML 键或别名都会拒绝。

3. 先预演，核对真实媒体检查及地址检查结果。

   ```sh
   npm run blog -- toy add --file ./toy.yaml --dry-run
   ```

   返回 `PLANNED`，不登记作品、不创建写作锁或生成新 ID，不联系 Yandu。预演仍会匿名请求项目地址，不能当离线开关。

4. 确认后登记。可以在终端确认，也可在核对预演后明确使用 `--yes`。

   ```sh
   npm run blog -- toy add --file ./toy.yaml --yes
   ```

   返回 `PREPARED` 和作品 ID，状态仍为“待媒体处理”。文件中的 `videoOverflow: reject` 已明确选择超限拒绝；没有该字段时，非交互模式不会根据 `--yes` 自动补齐授权。确需改为允许保留开头时，用下方显式覆盖：

   ```sh
   npm run blog -- toy add --file ./toy.yaml --video-overflow trim-start --dry-run
   ```

   参数优先于文件策略，确认输出后再执行。输入文件可带完整 UUID 的 `id`；省略时成功登记才生成新 ID，已有 ID 一律拒绝覆盖。同名作品允许存在，重复提交不含 ID 的填写文件会生成不同作品。

### 查询和重新检查

1. 查询本地登记资料，不检查网络或媒体，不修改文件。

   ```sh
   npm run blog -- toy list
   ```

   显示每项名称、完整 ID、资料路径及“待媒体处理”；无法读取的资料单独列出问题。

2. 用完整 ID 重新核对原文件摘要、解码和项目地址。

   ```sh
   npm run blog -- toy check dab121ae-6c14-4bea-9e88-a2c8a0a8f525
   ```

   未变化且检查通过时返回 `LOCAL_VALID`，不更新原登记文件或摘要。若原文件变化，返回 `SOURCE_CHANGED` 并列出变化字段，先停止后续联网与解码检查；若文件缺失或损坏，也会拒绝。当前没有视频替换或媒体处理入口，不用重新加入同一个 ID 绕过校验。

3. 脚本读取 JSON 时使用静默 npm 入口。

   ```sh
   npm run --silent blog -- toy list --json
   ```

   `PREPARED`、`LOCAL_VALID` 都只表示本地阶段；处理结果中的 `outputBytes` 和 `retainedSeconds` 均为 `null`。

## 确认结果

资料保存在 `content/toys/<UUID>/toy.yaml`，包含规范化名称、原文件引用、SHA256、原文件大小、原视频时长、公网检查时间及超限策略。Yandu 尚未接入，不生成压缩或裁剪产物。

## 影响与取消

生成模板与登记作品都先展示确认，默认取消。取消或预演不登记作品。登记时会核对源文件与填写文件未在确认期间变化；已有作品不覆盖，原媒体不修改。

当前舞台、构建与发布流程保持原行为，没有 `build/publish --toy`。Yandu 后续能力按[通用媒体验收目标](/reference/yandu-acceptance)实施后，才另行接入处理、冻结媒体和明确选择作品发布。

## 常见问题

**原视频不到 10 MB，是否已经完成？** 没有。当前记录的是原文件大小，不能证明未来压缩产物合格。

**网站在浏览器中能打开，CLI 却拒绝？** 这里要求匿名 HTTP(S) 成功响应，不使用浏览器 Cookie、登录信息或代理。认证失败、反爬拒绝、超时、内网 DNS、循环或超过五次重定向都会停止。网络检查总超时为 20 秒。

**工具缺失怎么办？** 先准备 `ffprobe` 与 `ffmpeg`；CLI 不会自动安装。伪造文件扩展名不能通过实际解码。

**同一份资料可以直接编辑吗？** 登记 YAML 的名称、简介等可手动修改后重新检查，保留 ID、生成的结构和摘要。`toy check` 不写回文件；原媒体变化会明确报错。
