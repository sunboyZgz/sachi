# 替换站点头像

## 什么时候用

希望替换首页、目录和文末署名使用的头像时使用。固定文件名便于替换，构建后的内容哈希负责刷新资源地址。

## 开始前

准备头部与半身 PNG，保留合适透明背景。它们是全站资源，不是文章附件。

## 操作步骤

1. 找到根项目 src/assets/avatar/。

   ```text
   src/assets/avatar/
     avatar-head.png
     avatar-half.png
   ```

   覆盖这两个源文件；不新增第二套头像。

2. 覆盖 avatar-head.png、avatar-half.png，名称不变。

3. 不在 Markdown、public 或文档站另存头像，也不改页面引用地址。

4. 预览首页、目录、文章末尾：前两处头部头像，末尾半身署名。

   ```sh
   npm run dev
   ```

   检查首页、目录及文末署名的实际落位。

5. 确认文章首屏、栏目分页与共享页头没有新增头像。

6. 正式发布按[全站基线](/release/baseline)单独接受资源变更。

   ```sh
   npm run blog -- publish <文章> --dry-run
   ```

   替换头像属于全站基线，执行时单独明确接受。

### 两个文件分别负责哪里

| 固定源文件 | 使用位置 | 不使用的位置 |
| --- | --- | --- |
| avatar-head.png | 首页简介、目录站名旁 | 文章首屏、栏目分页共享页头 |
| avatar-half.png | 正文结束后的作者署名 | 首页主视觉、文章开头 |

保留 PNG 透明通道，检查图像里没有误加的黑 / 白底和过大透明边距。替换源文件时名字与大小写完全一致，类型仍为真实 PNG；不要把 JPG 仅改名成 .png，也不要自己加时间戳文件名来规避缓存。

验证顺序是：保存同名源文件 → 开发预览看三个落位 → 接受全站资源基线 → 构建 / 发布 → 查公开版本。新图只存在本地却线上仍旧是正常的未发布状态；旧冻结包 / 回滚版本继续使用旧头像也是预期结果。

## 确认结果

静态导入生成新的内容哈希，新构建引用新地址，不是强制覆盖旧缓存 URL。

## 影响与取消

影响全站代码／资源基线，旧包仍保留旧资源。

## 常见问题

本地替换不会上线，需构建与发布。不直接修改 out 图片伪装源文件更新。

## 参数方式

本页步骤旁已给出对应写法与结果说明。完整参数可在[命令索引](/reference/commands)按操作名查看；示例占位符请换成实际值，已安装简短命令时可把 `npm run blog --` 换成 `blog`。
