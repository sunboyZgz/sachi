# 组织系列文章

## 什么时候用

一篇文章越写越长，想把后续内容拆成多篇，或者几篇已有文章需要按顺序阅读时使用。先查到文章与系列的 ID，再明确插入章节；正文怎么拆由作者决定。

系列属于一个固定栏目，不是新建第四个主栏目。每篇最多归属一个系列，系列与文章必须同栏目。

## 开始前

本页沿用“闲暇娱乐”的文章 **朝思暮想的玩具**、系列 **我学会了**。示例 UUID、目录日期仅供教学；命令中的 `<文章ID>`、`<系列ID>` 要替换成实际输出，尖括号不保留。

## 操作步骤

### 1. 按中文标题查文章 ID

只记得一部分标题也能查。搜索列出全部候选，不自动修改最相似的一篇：

```sh
npm run blog -- search "朝思暮想"
```

示例输出：

```text
文章搜索：朝思暮想
匹配 1 项：
朝思暮想的玩具 · 闲暇娱乐
  ID：51f3e126-f6a0-4ef3-a4fb-6dca72b85afd
  文件：.blog-store/content/闲暇娱乐/2026-10-12/index.md
```

核对栏目和文件，再复制 ID。同名、多个关键词及轻微错字的用法见[查找文章与系列 ID](/writing/find)。

### 2. 查系列，或创建一个

先根据名称查找，避免只凭名称重复创建：

```sh
npm run blog -- series search "我学会了"
```

存在时返回以下形式的候选，同名系列仍分别显示 ID：

```text
系列搜索：我学会了
匹配 1 项：
我学会了 · 闲暇娱乐
  ID：a712a8ac-2c18-4520-9428-96a45b566ce1
  文件：.blog-store/content/series/a712a8ac-2c18-4520-9428-96a45b566ce1.yaml
```

没有合适系列时，在原文章的栏目创建：

```sh
npm run blog -- series new --category play --title "我学会了"
```

终端询问可留空的简介，核对并确认后创建。成功输出直接给出可复制的新 ID：

```text
series：已创建
系列：我学会了
栏目：闲暇娱乐
ID：a712a8ac-2c18-4520-9428-96a45b566ce1
文件：.blog-store/content/series/a712a8ac-2c18-4520-9428-96a45b566ce1.yaml
```

每次实际创建生成新的 UUID。创建命令加 `--dry-run` 只显示计划，不生成可用于下一步的 ID。

### 3. 将原文章作为第一章

替换两个完整 ID，先看变更列表，再去掉预演参数执行：

```sh
npm run blog -- series add <文章ID> --series <系列ID> --order 1 --dry-run
```

输出显示原文章“普通文章 → 1”和需要顺延的章节；此时没有写入。核对后执行：

```sh
npm run blog -- series add <文章ID> --series <系列ID> --order 1
```

最终确认后，原文章的 ID、slug、创建时间、正文和资源保持原样，frontmatter 增加：

```yaml
series:
  id: a712a8ac-2c18-4520-9428-96a45b566ce1
  order: 1
```

文章已属于任何系列时，add 提示原归属并拒绝，包括重复加入同一个系列。它不自动搬迁或调整已有文章的位置。查看或显式退出旧系列仍使用[文章信息操作](/writing/edit-meta)。

### 4. 拆出后续文章，再插入

创建另一篇普通文章，把原文后续内容移过去；所引用图片、附件与 media.yaml 配置也移入对应新文章。CLI 不自动判断拆分边界：

```sh
npm run blog -- new --category play --title "让玩具真正用起来"
```

如果出现“所属系列”选择，先选“普通文章，不加入系列”，记下新文章 ID，再让插入命令负责归组：

```sh
npm run blog -- series add <新文章ID> --series <系列ID> --order 2 --dry-run
```

插入 2 时，**所有序号不小于 2 的章节都加一**，包括未发布草稿；2 当前空闲也一样。核对后去掉 `--dry-run` 执行。

| 原序号 | 插入后 | 原因 |
| --- | --- | --- |
| 1 | 1 | 插入点之前保持原样 |
| 新文章 | 2 | 指定的新章节 |
| 10 | 11 | 后续草稿顺延，保留间隔 |
| 20 | 21 | 不把全系列重排为连续编号 |

`--order` 是章节序号，不是当前列表第几项。需要顺延的公开章节缺少本地源文件时，必须先恢复原稿。

### 5. 检查正文并预览

写作完成后检查元数据和素材，再打开开发预览：

```sh
npm run blog -- check <文章ID> <新文章ID>
npm run blog -- dev --post <新文章ID>
```

文章标题下有系列入口，正文后有章节导航。开发预览读取本地内容；正式目录只列已公开章节，不显示草稿名称或数量。

### 6. 公开时一起选择被顺延的已发布章节

插入结果列出所有受影响 ID；`publishTogether` 根据本地上次发布清单提示新增文章和需重发的公开章节。未发布草稿可以继续留在本地。

例如新增文章占用原公开第 2 章的位置，旧第 2 章已变为第 3 章，先同时选择两篇查看计划：

```sh
npm run blog -- publish <新文章ID> <原第2章ID> --dry-run
```

核对每篇将公开的完整修订，再执行同一选择并核实线上状态：

```sh
npm run blog -- publish <新文章ID> <原第2章ID>
npm run blog -- status --remote
```

遗漏旧公开第 2 章会被重复序号检查拒绝。CLI 不为修正导航顺带发布其他文章的新稿。只改系列介绍时仍可明确使用 `publish --series <系列ID>`；不会因此重发文章正文。

## 确认结果

返回 UPDATED，列出新增归属和每篇顺延前后的序号；正文、YAML 注释、换行形式和身份保留。明确发布后，`/series/<slug>/` 按章节序号列出公开文章，上一篇／下一篇跳过草稿。

## 影响与取消

搜索只读。创建和插入只影响本地；输入或最终确认取消不会提交新的插入，dry-run 不写文章或执行恢复。如果存在未完成事务，正常执行时恢复步骤先把旧文件还原，再询问新插入的确认。多文件写入失败会回滚，恢复记录位于 `.blog-store/writing-transactions/`，不能当缓存删除。公开快照、旧哈希和线上内容不因本地顺延而改变。

异常中断后再次执行 series add 会先恢复旧文件，再重新规划。未恢复期间其他写作修改与构建发布暂停，查询仍可使用。若旧进程留下锁，先确认进程确实结束，再按锁提示移除 `.blog/writing.lock`；不移除其他正在使用的锁。发现额外编辑或文件缺失则保留备份并拒绝覆盖，见[事务恢复](/troubleshooting/errors#系列插入中断后的恢复)。

## 常见问题

- **名称相同**：核对候选的栏目和文件路径，再复制 ID。
- **已有归属**：add 拒绝，使用 meta 查看原归属；不会自动换系列。
- **正式目录还没出现**：至少一篇章节明确发布后才生成目录。
- **本地顺延，线上未变**：保存不是发布，需明确选择受影响公开章节。
- **修改介绍**：`series meta <系列ID> --set 'description=新的简介'` 只改本地；发布该系列章节时同步采用。
- **退出系列**：`meta <文章ID> --set 'series=null'` 只修改该篇，不重新编号其他章节。
