# 设置文字环绕图片

## 什么时候用

文章开头需要文字沿插画、植物、物件等图片轮廓环绕时使用。图片不限定茶杯，尺寸按原图比例计算。

## 开始前

已有本篇静态图片。透明图片会按 alpha 自动生成轮廓；不透明图片按矩形环绕。可以提供手工轮廓替代自动结果，但不需要自己先生成 JSON。不能使用动画或短视频作为环绕障碍。

## 操作步骤

1. 把静态图片放入本篇 `assets/illustration.png`，不要复制站点头像。如果图片有 EXIF 旋转，先在图片编辑器中修正方向再保存。

2. 在 frontmatter 添加下面的 flow，不增加 layout.yaml。

   ```yaml
   flow:
     image: ./assets/illustration.png
     width: 240
     defaultX: 0.53
     defaultY: 86
   ```

   把这些字段合入原 frontmatter，保留身份信息。

3. 正文开头是纯文本段落与一张独立图片 `![植物插画](./assets/illustration.png)`，路径必须与 `flow.image` 相同。替代文字取自图片说明，也可以用 `flow.alt` 覆盖；不会写死成“一杯茶”。

4. 首个二级标题前不放列表、代码块、复杂链接或其他图片。Markdown 用 AST／GFM，Pretext 只处理局部纯文本。

5. 运行 `npm run blog -- check <文章>` 后预览桌面效果。省略 `contour`，预览和构建会从同一画布生成哈希轮廓文件；若指定 `contour`，则读取本篇现有 JSON。

   ```sh
   npm run blog -- check <文章>
   npm run blog -- dev --post <文章>
   ```

   完成资源与结构检查，再打开桌面预览。

6. 按图形调整 `width`（桌面最大宽度）、`defaultX`（横向中心比例）和 `defaultY`（顶部像素位置）。默认宽度 205 px；范围 96–360 px，超过 360 px 高时等比缩小。位置限制在可拖动区内，不裁边、不拉伸。

7. 开启互动后可拖动图片或用方向键移动，点击“还原位置”恢复配置位置。互动只改变本次阅读，不写回 Markdown，也不会自动滚动正文。

8. 检查移动端、普通排版和打印。屏幕宽度不超过 600 px、正文宽度小于 520 px、无 JavaScript、图片/轮廓加载失败或引擎异常时，完整段落仍以普通 DOM 存在。

### 参数与排版边界

| 字段 | 默认 / 范围 | 作用 |
| --- | --- | --- |
| image | 必填，本篇静态图片 | 与引导区的独立图片地址相同 |
| contour | 可省略 | 省略沿 alpha 自动生成；指定时读取本篇 JSON |
| width | 默认 205，96–360 px | 最大显示宽度，不是强制拉伸宽度 |
| defaultX | 默认 0.53，0–1 | 引导区域中水平中心的比例，不是像素 |
| defaultY | 默认 86，非负像素 | 初始顶部位置；显示时受可移动区域限制 |
| alt | 可省略，非空时最多 300 字符 | 覆盖独立图片说明作为替代文字 |

一个文章只定义一个 flow，引导区域止于**第一个二级标题**。图片可以夹在纯文本段落之间，但必须独占一个段落；不要让文字紧贴在同一行。强调、链接、引用、列表、代码块、表格和其他图片全部放在该二级标题之后，才能使用普通 Markdown 渲染。

环绕段落也可以在开头写 `::正文`，生成两个字宽的首行缩进。需要段内紧凑换行时，在上一行末尾写 `\`，下一行写 `::正文`，不要留空行；环绕仍按同一段落处理，空行才会增加段落间距。窄屏、普通排版和打印会保留相同的显式换行与缩进。段落内容仍需满足纯文本限制。

正文写 `**重点**` 在环绕区不是“效果更丰富”，而是校验失败；把它移到标题后即可。media.yaml 也不能代替 flow，手册本身的 `::: tip` 提示框语法不属于博客正文支持的语法。

## 确认结果

桌面局部环绕，横图和竖图保持原始比例；移动端、打印、引擎异常时完整正文保留。图片与配置冻结，自动轮廓由冻结图片和冻结代码生成，旧计划不采用新图。

## 影响与取消

删除 `flow` 可恢复全篇普通 Markdown，但图片仍保留在正文中。只删除 `contour` 会改用自动轮廓，不会禁用环绕。自动过程只读取源图，不改写原图。

手工轮廓仍兼容：在本篇 `assets/illustration-contour.json` 中放 `{ "height": 行数, "rows": [...] }`；每行是 `null` 或归一化的 `[左界, 右界]`，满足 `0 ≤ 左界 ≤ 右界 ≤ 1`，行数匹配 `height`（1–8192），至少一行有形状。设置 `contour: ./assets/illustration-contour.json`。轮廓应对应整幅画布，不先裁掉透明边距。

## 常见问题

- 自动轮廓像矩形：源图可能没有透明通道；这是正常降级，不会分析图像内容自动抠图。
- 完全透明或带旋转的图：先修正源图；动画先导出静态帧。
- 路径不同、手工轮廓格式错误或引导区有富文本：检查会指出错误。
- 很长的正文：仍需有首个二级标题；复杂块放在该标题后。发布 B 不会采用 A 的新环绕位置。

验证时先看页面正文宽度，不只看整个窗口宽度。窄侧栏或阅读框可能触发普通排版，这是完整正文降级，不是功能没加载。互动模式的图片位置只保存在本次阅读中；想固定新位置，要修改源文件的 defaultX / defaultY，再明确重新发布本篇。
