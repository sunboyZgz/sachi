# 设置文字环绕图片

## 什么时候用

想让正文沿插画或物件轮廓环绕时使用。图片可以在文章开头、中间或结尾，文章不必有标题；`#`、`####` 等标题都能分隔区域。参数继续放在 frontmatter，正文仍是普通 Markdown 图片。

## 开始前

准备本篇静态图片。透明图片按 alpha 自动生成轮廓，不透明图片按矩形环绕；也可提供手工 JSON。动画、视频和完全透明的图片不能作为环绕障碍。图片有 EXIF 旋转时，先显式修正方向。不要复制站点头像。

## 操作步骤

1. 把图片放入本篇 `assets/illustration.png`，把配置合入原 frontmatter，保留 `id`、`title`、`createdAt` 等身份信息。

   ```yaml
   flow:
     image: ./assets/illustration.png
     width: 180
     defaultX: 0.53
     defaultY: 54
   ```

   `width: 180` 表示完整图片画布显示为 180px 宽，保持比例，包括透明留白。容器不足才缩小，高图不会因为超过 360px 高而缩窄。

2. 在需要的位置放一张独立图片，前后写普通文字；空行只分段，不结束环绕。

   ```markdown
   ::图片前的一段正文。\
   ::紧凑换行后的缩进文字。

   ![植物插画](./assets/illustration.png)

   图片后的正文也参与同一区域。

   #### 后续小节

   这里可以写 **强调**、链接和其他 Markdown。
   ```

   识别会从图片向两侧收集连续纯文本段落。任意层级标题、分隔线、列表、引用、表格、代码、富文本段落或另一张普通图片都是边界；边界内容照常显示。引用式图片也支持，例如 `![植物][plant]` 配合 `[plant]: ./assets/illustration.png`。

3. 多张图片分别配置。两个连续候选区之间需要任意标题、分隔线或普通块，空行不足以分隔。

   只删除 contour 会恢复自动轮廓；删除整个 flow 会恢复普通 Markdown。原图不会被裁边或改写。

5. 保存后用 CLI 检查，再查看网站预览。把占位符换成文章 ID、slug 或路径。

   ```sh
   npm run blog -- check <文章>
   npm run blog -- dev --post <文章>
   ```

   CLI 会报告重复配置、配置图未出现在正文、图片混入文字或嵌在列表/引用中等具体问题。独立图片旁没有连续纯文本时会提示原因，按配置宽度普通显示。

6. 在 VS Code 中无需保存即可调整宽度和默认位置。预览默认跟随面板宽度；命令 **Sachi Blog: 切换桌面宽度／响应式预览** 可切到 720px 正文，在窄面板横向滚动。

   ```json
   { "sachiPreview.layoutMode": "responsive" }
   ```

   用 `desktop` 可设置默认桌面模式；面板内切换只影响本次预览。状态会显示“环绕”“普通图文”或“降级”及原因，只有真正启用引擎才显示环绕。

7. 在网站开启互动，拖动结束或用方向键移动后，浏览器会分别记住每篇文章、每处环绕图片的位置。刷新页面或下次回来阅读，会自动恢复文字环绕和图片位置；移动端仍用普通排版，返回桌面后恢复记忆。

   点击“还原位置”会清除这一处记录，并恢复作者的 defaultX / defaultY。横向位置按比例适应窗口宽度，图片和配置发生变化时采用新配置。记录只属于同一浏览器、同一站点，清除网站数据后恢复默认；存储不可用时仍能正常阅读和互动。

   VS Code 写作预览和本页教学示例保留临时位置，方便作者核对默认排版。

8. 单击普通图片或未开启互动的环绕图片，编辑器光标回到对应 Markdown 图片语句起点；引用式图片回到正文引用语句。文字仍按原行列定位。开启互动后图片用于拖动和方向键移动，不跳转源码。

9. 检查窄屏、普通排版、打印和失败降级。普通 DOM 按原顺序保留图片和全部段落，图片使用同一配置宽度和原始比例。

### 参数与排版边界

| 字段 | 默认 / 范围 | 作用 |
| --- | --- | --- |
| image | 必填，本篇静态图片 | 对应正文独立图片或引用定义的资源路径 |
| contour | 可省略 | 自动读取 alpha；指定时使用本篇 JSON |
| width | 默认 205，96–360 px | 完整画布显示宽度，仅在容器不足时缩小 |
| defaultX | 默认 0.53，0–1 | 本环绕区域内，图片水平中心占区域宽度的比例 |
| defaultY | 默认 86，非负像素 | 本区域顶部到图片顶部的距离，显示时受可移动范围限制 |
| alt | 可省略，非空时最多 300 字符 | 覆盖正文图片说明作为替代文字 |

保留单对象写法；多图使用数组，每项独立填写这些字段。没有 flow 的文章保持标准 Markdown。列表、引用内部的图片保持普通展示，不能用作顶层环绕区域。

`::` 生成约两个字宽的首行缩进。上一行末尾写 `\`，下一行写 `::正文` 可紧凑换行；普通回车仍是软换行，空行才增加段落间距。这些写法在环绕与降级中保持一致。

## 确认结果

桌面局部环绕，图片宽度可直接量到；手机、打印、无 JavaScript、轮廓或引擎错误时完整正文保留。不同区域的默认位置分别计算，修改参数立即重新排版并还原该区域的临时拖动位置。

## 影响与取消

调整 flow 只修改本地资料，需要明确重新发布本篇才会更新公开文章。所有配置图片和手工轮廓进入冻结快照；自动轮廓从冻结图片生成。发布其他文章不会采用本篇未选修订。

删除 flow 可恢复普通 Markdown，图片仍按正文位置显示。网站拖动结果保存在读者浏览器的 localStorage 中，文章和公开快照保持原样；“还原位置”会清除对应记录。

手工轮廓格式为 `{ "height": 行数, "rows": [...] }`。每行是 `null` 或 `[左界, 右界]`，满足 `0 ≤ 左界 ≤ 右界 ≤ 1`；行数匹配 height（1–8192），至少一行有形状。轮廓对应整幅画布，不裁掉透明边距。

## 常见问题

- 图没有环绕：先看状态原因。正文宽度小于 520px、手机模式、结构未完成或资源失败会普通展示。插件可切桌面模式查看。
- 宽度看起来没变化：透明留白也是画布的一部分；width 控制画布，不自动放大其中的可见物件。
- 富文本旁的图片没有环绕：富文本是边界；在另一侧添加纯文本即可参与。附近没有纯文本时按宽度普通展示。
- 多图连续时报错：在两张配置图片之间加入 `---`、任意标题或其他普通块，不需要固定的 `##`。
- 自动轮廓像矩形：不透明源图会使用矩形，不会自动抠图。
