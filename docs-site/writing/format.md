# 整理正文中英文空格

## 什么时候用

中文正文夹着英文词语，又不想逐个手动补空格时使用。比如：

```text
原文：我们正在使用AI改变世界。
结果：我们正在使用 AI 改变世界。
```

这是主动执行的本地写作操作；新建、检查、构建与发布不会自动调用它。

## 开始前

先保存编辑器中的文章，再用 [search 查文章 ID](/writing/find) 或准备文章的 slug、项目相对路径。它兼容旧的 `content/*.md`，只处理明确选择的正式文章；不默认采用全部草稿。正文或 flow 尚未完成、配图尚未准备时，也可以整理空格。

## 操作步骤

1. 先预演，查看要修改的原始行号和前后文字。

   ```sh
   npm run blog -- format autumn-tea --dry-run
   ```

   输出示例紧随命令，实际行号以自己的文章为准：

   ```text
   format：计划（未执行）
   选中 1 篇，需修改 1 篇，共补 2 个空格。
   ……
     第 11 行
   - 我们正在使用AI改变世界。
   + 我们正在使用 AI 改变世界。
   未写入文件。
   ```

2. 核对后执行。交互终端会再次显示差异，再询问确认；脚本需要显式确认。

   ```sh
   npm run blog -- format autumn-tea
   # 已核对计划，在脚本或非交互终端中执行：
   npm run blog -- format autumn-tea --yes
   ```

   成功显示 `format：已修改` 和逐行差异。再次运行时，不会重复补空格；无变化显示 `format：无需修改`。

3. 有需要保留的词语时，加入可重复的 `--ignore`，先检查效果。

   ```sh
   npm run blog -- format autumn-tea --ignore "维生素B12" --ignore "OpenAI" --dry-run
   ```

   ```text
   原文：维生素B12与OpenAI项目，再使用AI。
   结果：维生素B12与OpenAI项目，再使用 AI。
   ```

   默认保留 `A股`、`B股`、`H股`、`A站`、`B站` 的连写。忽略词语按字面匹配，不推断品牌或专业术语；与忽略词语重叠的英文词保持原写法。

4. 多篇文章可以一次明确选择；也可在主菜单选择“整理正文中英文空格 · format”，勾选文章后，默认先看计划。

   ```sh
   npm run blog -- format autumn-tea another-note --dry-run --json
   ```

   JSON 的 `data.articles` 包含每篇的 ID、路径、补空格数和 `changes: [{ line, before, after }]`，`data.changedArticles` 与 `data.insertedSpaces` 是总数。

5. 保存结果后查看 [文章预览](/preview/dev)。文章已公开时，仍需 [明确发布这篇修订](/release/update)，原公开快照不会被格式化命令改写。

## 确认结果

处理正文中的段落、标题、引用、列表、表格单元格，以及强调和普通链接的可见文字。例如：

```md
原文：我们使用**AI**改变世界，也学习[React](https://example.org/)。
结果：我们使用 **AI** 改变世界，也学习 [React](https://example.org/)。
```

含英文的词组支持 `GPT-4`、`Node.js`、`C++`、`C#`、`3D` 等写法。纯数字不是本次处理对象，`2026年` 保持原样。

代码块、行内代码、数学公式、自动网址与邮件链接、图片说明、原始 HTML、引用定义、链接目标和标题参数保持原样。不会补标点间距，也不会强制给代码或公式两侧加空格。

文章 frontmatter（包括页面标题、ID、slug、series、flow）、YAML 注释、资源路径、换行形式、BOM、行尾空格与末尾换行保持原样。格式化后，网站、预览和环绕引擎都读取同一份实际文字。

## 影响与取消

确认前取消不会修改正文；`--dry-run` 不登记事务、不恢复旧事务、不写文件。写入时复用写作锁，并在 `.blog-store/writing-transactions/` 保存恢复记录；多篇写入失败会回滚，确认后发现文件被额外修改会拒绝覆盖。

如果发生异常中断，再次执行 `format <文章>` 会先恢复未完成的事务，再重新计算并展示差异。存在额外编辑时保留恢复记录并拒绝覆盖；未恢复的事务会阻止后续写作修改和构建发布。原媒体、公开快照和远端均不改动。

## 常见问题

- 找不到文章：使用完整 ID 或具体路径。中文标题应先用 search 查找，不按名称模糊匹配后自动修改。
- 标题没变：这里只处理正文中的 Markdown 标题；frontmatter 的页面标题保持原样。
- 某处未补空格：已有空白、标点或受保护内容隔开时不强加空格；未形成格式的 Markdown 符号按普通文本处理。先修正语法，再预演。
- 想保留品牌或专业记号：使用 `--ignore`，不要依赖自动识别含义。
- 刚才在编辑器修改过：先保存再执行；CLI 无法读取尚未保存的编辑缓冲区。
