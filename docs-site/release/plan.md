# 读懂计划，先不执行

## 什么时候用

执行构建、发布、撤回或回滚前，先看清本次会选中、保留和排除哪些内容。预演只展示计划，不冻结修订。

## 开始前

已有正式文章。先检查正文和资源，不把 fixture 当作可发布文章。

## 操作步骤

1. 进入本地构建或发布菜单，空格勾选本次明确选择的文章。

2. 选择“只查看计划”。发布未配置部署时不会进入实际发布。

   ```sh
   npm run blog -- build <文章> --dry-run
   ```

   没有部署配置也能预演本地构建。

3. 核对本次选择：这些文章采用当前修订；核对保留旧快照：未选公开文章仍用旧文字和资源。

   ```sh
   npm run --silent blog -- publish <文章> --dry-run --json
   ```

   已经配置部署时，查看 selected、unchanged、excluded 与 delivery。

4. 核对不公开的本地文章与历史撤回信息。没有选中的草稿不会自动带入。

5. 查看全站代码／配置基线是否变化；旧快照缺失时检查 pendingSnapshotChecks 提示。

6. 计划输出后命令退出。执行时要重新进入并重新核对新计划，release-id 可能变化。

### 一个最常见的计划：只更新 B

假设上次公开了 A、B；现在 A、B 都有本地修改，又新增草稿 C。本次只选择 B：

| 文章 | 计划中的位置 | 候选网站采用什么 |
| --- | --- | --- |
| A | unchanged / 保留旧快照 | 上次公开的 A；不采用当前 A 新稿或新图片 |
| B | selected / 本次选择 | 确认时冻结的 B 正文、元数据、引用素材和媒体配置 |
| C | excluded / 不纳入公开 | 不生成 C 页面；不因被扫描而公开 |

如果 B 引用了 C，计划会拒绝未发布引用；需要明确把 C 一起选中，或删除该链接。不能依靠“它是草稿”让失效链接继续公开。

### 对照输出逐项核对

- `manifest.releaseId`：本次候选 ID；预演生成的 ID 不能拿去 resume。
- `manifest.baseReleaseId`：基于哪个旧版本；不是把任意旧包覆盖到当前网站。
- `selected`、`unchanged`、`excluded`：分别是选中、沿用旧快照和排除的文章 ID；人类输出会显示标题与数量。
- `baselineChanged`：整站代码、个人资料或资源是否变化；true 时需要单独接受影响范围。
- `pendingSnapshotChecks`：本地缺哪些旧快照。出现它意味着最终校验尚未完成，不是“会用工作副本补上”。
- `delivery`：publish / unpublish 的服务器和 Pages 目标；核对仓库、blog 分支、网站 URL 和是否设置 Pages。

想查看完整字段，用 `npm run --silent blog -- publish <文章> --dry-run --json`。没有配置目标时可先预演本地 build；不要为了获得计划而填一个并不存在的服务器。

## 确认结果

返回 PLANNED；不会保存冻结计划、提交、上传、切换 current 或完整执行构建。

## 影响与取消

--dry-run 不写持久快照或发布记录，必要的服务器查询是只读操作。

“不写入”指不修改文章、不冻结对象、不执行提交 / 部署；不是离线保证。已经配置的目标可能需要只读查询，所以网络不可用时预演也可能失败。

## 常见问题

预演通过不等于完整构建通过。预演的 ID 不是可 resume 的冻结发布 ID。旧快照缺失必须恢复，不能用工作副本替代。
