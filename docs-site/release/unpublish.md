# 撤回公开文章

## 什么时候用

某篇公开文章暂时不应继续展示时使用。撤回改变公开集合，保留本地原稿，不等于删除所有历史副本。

## 开始前

文章当前在已核实的公开清单中。先检查其他公开文章是否仍链接它。Pages-only 要先等当前版本部署完成并核实，不能从排队版本开始撤回。

## 操作步骤

1. 先修改并发布仍引用目标的文章，或者确认不存在此类引用。

2. 进入“撤回公开文章 · unpublish”，读取已配置目标的当前公开列表。

3. 空格勾选要撤回的文章。即使本地原文缺失，也能选择服务器条目。

4. 先看计划，确认本次撤回目标与保留文章。

   ```sh
   npm run blog -- unpublish <文章> --dry-run
   ```

   计划核对撤回目标和保留公开文章。

5. 重新进入执行，接受必要代码基线变更并核对最终确认。

   ```sh
   npm run blog -- unpublish <文章>
   ```

   确认后撤回，保留本地原文与历史身份。

6. 用远端状态与网站页面验证目标不再公开。

   ```sh
   npm run blog -- status --remote
   ```

   核实公开清单与真实页面，不只检查本地文件。

### A 仍链接 B，怎样撤回 B

先修改 A，删除或改写指向 B 的链接，检查并只选 A 发布；等这个版本核实成功后，再 unpublish B。即使当前 A 工作副本已经删除了链接，只要 A 还没重新发布，它的旧公开快照仍引用 B，撤回检查就会阻止操作。

撤回会重新构建保留文章的集合，更新目录、分页与站点地图，不只是隐藏某一条列表。撤回最后一篇文章也可以形成空站；仍须明确选择目标、构建和交付，不能通过删除 out 或原稿完成。

### 之后再公开同一篇

保留原稿的 id、slug 与创建时间，修改、检查后再次明确 publish 这篇文章即可。历史首次发布时间保留，更新时间改变。需要完全独立的新文章则用 new，不给旧身份换 UUID 来规避历史约束。

## 确认结果

新清单不含目标；本地原稿不删，历史 ID、slug 与首次发布时间保留。

## 影响与取消

撤回不保证互联网缓存或读者保存的副本消失，也不是删除私有历史发布包。

Pages 的旧正文还可能保留在 blog 分支 Git 历史中；unpublish 不是隐私擦除，不会重写 Git 历史。Pages 返回 PUSHED 后仍须等待 Actions 并核实标记，不能只看本地原稿仍在就判断撤回失败。

## 常见问题

本地删除不会自动撤回。已撤回文章不能当成从未发布过来修改 slug。仍被公开文章引用会阻止构建。
