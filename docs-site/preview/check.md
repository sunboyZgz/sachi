# 检查 Markdown 与资源

## 什么时候用

发布前，或新增资源、站内链接和 flow 配置后，检查 Markdown 与依赖。它不会冻结文章或执行上线。

## 开始前

文件已保存；视频检查需要 ffmpeg 与 ffprobe。检查可以包含 fixture。

## 操作步骤

1. 进入“检查 Markdown 与资源 · check”。

2. 选择全部本地文章，或选择文章并空格勾选。

3. 查看元数据、AST、依赖路径与媒体校验结果。被代码块包围的示例引用不是实际依赖。

4. 按报错文件修复，例如缺图、重复身份、越界引用、原始 HTML 或不支持的媒体。

5. 再次检查，确认 VALID；注意 warnings 并不等于可以忽略所有发布约束。

6. 发布前再[查看计划](/release/plan)，确认跨文章链接的目标也会公开。

### 一次错误该怎样修

例如正文写了 `![茶杯](./assets/cup.png)`，却只放入了 `Cup.png`：先核对报告中的 file 与引用，再统一实际文件名和 Markdown 大小写。不要把路径换成电脑的绝对地址，也不要移进 public 来绕过本篇资源规则。

常见处理顺序是：frontmatter 能解析 → id / slug 不重复 → 资源存在且不越界 → 视频 / 图片可处理 → flow 引导区合法。只检查一篇时，仍会扫描整份内容库；其他文章的结构错误也可能阻止检查，应按报告定位，不代表 CLI 选错文章。

### VALID 中的字段怎么读

`posts` 列出本次检查的文章；每篇的 `dependencies` 列出真正引用的资源和字节数 / 哈希；`warnings` 给出警告。找不到预期附件时，确认它在正文或 cover / flow 中有真实引用，而不是只写在代码块的教学例子里。

check 验证当前文件，不生成处理后的媒体、不保存发布快照，也不进行全部公开文章的最终链接校验。它不能保证外部网站可用、Actions 会成功或搜索引擎收录；下一步仍需计划和实际构建。

## 确认结果

返回 VALID 与文章、资源、警告信息。内容扫描存在其他结构错误时也可能阻止选中检查，应先处理扫描问题。

## 影响与取消

只检查，不创建快照或改写正文，不替换原素材。

## 常见问题

check 不代表完整隔离构建通过，也不代表链接目标已公开。不要用改扩展名绕过媒体检查。

## 参数方式

尖括号是占位符，应换成实际文章或目录，不要原样执行。未安装简短命令时用 `npm run blog --`；已安装时可替换成 `blog`。

```sh
npm run blog -- check
npm run blog -- check <文章A> <文章B>
npm run --silent blog -- check <文章> --json
```
