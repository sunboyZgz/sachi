# 预览首页或文章

## 什么时候用

新建文章、修改正文或调整资源后，先在本地看实际阅读效果。开发预览包含当前写作，不代表公开版本。

## 开始前

本地 Markdown 已保存，当前没有占用 127.0.0.1:4173 的其他开发服务器。预览读取根目录 `content/` 的真实工作内容，允许草稿，但不加载测试样例。

## 操作步骤

1. 进入“预览首页或文章 · dev”。

2. 选择首页，或选择要查看的文章。

   ```sh
   npm run blog -- dev --post <文章>
   ```

   指定要预览的实际 ID、slug 或路径；只看首页可运行 dev。

3. 等待终端输出 PREVIEW 与地址，再等待 Next.js 开发服务器就绪。

   ```text
   PREVIEW
   地址：http://127.0.0.1:4173/article/<实际slug>/
   ```

   这是地址形式示意，以终端实际地址和服务器就绪日志为准。

4. 在浏览器打开输出地址。CLI 不会自动弹出浏览器。

5. 修改并保存 Markdown，查看刷新后的正文、图片、视频和环绕效果。

6. 在启动服务器的终端按 Ctrl+C 停止。

### VS Code 未保存预览

在项目根目录构建并生成插件：

```sh
npm run preview:build
npm run preview:package
```

将 `tools/vscode-preview/dist/sachi-blog-preview.vsix` 从 VS Code 的“从 VSIX 安装”入口安装。打开文章后运行 **Sachi Blog: 打开文章预览**，输入无需保存即可刷新；普通图片和非互动环绕图片可单击定位源码。

插件也支持[完整稿件](/writing/drafts)中的原文、导出的旧稿和任意位置符合博客格式的 Markdown。直接打开旧稿目录中的 `content/<栏目>/<日期>/index.md`，即可预览当时的原文及其 `assets/`，不需要放回当前内容目录。旧式导出稿从自己的 `public/assets/` 读取资源。

如果文章单独存为 `~/writing/随笔.md`，在 frontmatter 中提供栏目即可：

```markdown
---
id: 51f3e126-f6a0-4ef3-a4fb-6dca72b85afd
title: 独立文章
category: life
createdAt: "2026-10-10T09:00:00+08:00"
---

正文。

![插画](./assets/illustration.png)
```

打开该文件后运行预览命令，会显示“生活旁白”、标题、日期和 `~/writing/assets/illustration.png`。不必打开整个项目；没有关联的 Sachi 项目时使用插件自带样式与署名。栏目也可由三个中文栏目目录识别；普通 README、教程 Markdown 不会替换当前文章。此能力只扩展插件预览范围，CLI 的正式文章目录与发布规则不变。

预览默认跟随面板宽度。运行 **Sachi Blog: 切换桌面宽度／响应式预览** 可查看 720px 桌面正文，窄面板横向滚动。设置写法如下，效果紧随配置生效：

```json
{ "sachiPreview.layoutMode": "responsive" }
```

改成 `desktop` 可设置默认桌面模式。环绕状态会显示真实布局及降级原因，配置与[多图教学效果](/writing/flow)共用网站解析。插件详细用法见项目 `tools/vscode-preview/README.md`。

引用、列表、表格和代码共用网站排版，不随 VS Code 的浅色或深色主题改变。对照桌面网页时选择桌面模式；对照手机时让响应式面板采用同一宽度。网站显示已保存正文，插件包含未保存修改，比较前先确认两边内容版本一致。

`type: poem` 会在网站与插件中同时启用诗歌排版：单次回车即诗行换行，空行分诗节，标题与诗行居中；修改未保存的 type 也立即刷新。诗行仍可跟随定位和单击回到源码，见[诗歌教程](/writing/poetry)。

`++文字++`、`--文字--` 与带倍数的 `++文字++{2}`、`--文字--{2}` 也共用网站字号规则；修改倍数会即时更新，文字点击仍按原行列定位。写法与相邻效果见[调整文字字号](/writing/text-size)。

### 两个终端的日常用法

终端 A 启动预览，并让它持续运行：

```sh
npm run blog -- dev --post autumn-tea
```

终端 B 也切到 sachi 根目录，用于编辑后的检查：

```sh
npm run blog -- check autumn-tea
```

`autumn-tea` 是[本地教程](/start/local-workflow)中的 slug，换成自己的实际 slug / ID / 相对路径。正文修改后先保存，等待开发服务器重新处理；没变化时刷新浏览器。新增图片、换同名素材或新增文章后也要检查，避免把旧页面缓存误认成新结果。

### 预览时逐项看什么

1. 首页 → 目录 → 所在栏目 → 文章，确认栏目名称和文章路径正确。
2. 点击文章目录与标题旁的 `#`，确认地址片段和定位一致；复制代码确认没有按钮文字混入。
3. 打开图片、播放视频、点击附件和站内文章链接。
4. 有 flow 时检查桌面环绕、普通排版开关、移动端完整正文，见[环绕验收](/writing/flow)。

这些是当前写作的检查，不是公开版本的验收。要确认“哪些文章真的会导出”，使用[隔离构建](/release/build)，不要把开发服务截图当作发布证明。

## 确认结果

首页地址为 http://127.0.0.1:4173/，文章地址为 /article/&lt;slug&gt;/。预览读取当前工作内容。

维护页面排版时可运行 `npm run dev:fixtures`，在 http://127.0.0.1:4176/ 显式查看 `tests/fixtures/content/` 中的测试正文。该服务使用独立缓存；`npm run test:browser` 自动启动它，不占用日常预览。

## 影响与取消

不提交、不上线。不要把开发预览包含草稿当作生产构建也会公开草稿。

## 常见问题

端口占用时优先使用已启动的服务器，或由你确认停止它；不要同时启动两个。找不到文章时确认 ID、slug 或路径。

## 参数方式

本页步骤旁已给出对应写法与结果说明。完整参数可在[命令索引](/reference/commands)按操作名查看；示例占位符请换成实际值，已安装简短命令时可把 `npm run blog --` 换成 `blog`。
