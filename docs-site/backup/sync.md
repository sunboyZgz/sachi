# 备份全部写作

当前项目的完整私有备份使用[私有资料仓库](/backup/store)：原稿与历史统一在 `.blog-store/`，通过 `npm run backup` 提交推送。原 `blog sync/restore` 仍兼容内容分支格式，两者不是同一份仓库布局。

## 什么时候用

想保存包含未发布草稿在内的全部写作时使用。Git 内容备份与公开网站完全独立；未配置时明确跳过。

## 开始前

已配置备份远端、专用内容分支并确认实际可见性。远端可复用代码仓库；全部写作备份可能包含草稿，公开仓库中的备份分支也公开。具体选法见[仓库与分支](/setup/git)。

## 操作步骤

1. 进入“保存全部写作备份（不上线）· sync”。

2. 先看计划，了解将备份的全部写作文件，而不是只选中的公开文章。

   ```sh
   npm run blog -- sync --dry-run
   ```

   PLANNED 列出全部写作备份范围；未配置 Git 时 SKIPPED。

3. 未配置 Git 时停止于明确跳过，不创建根 Git 仓库或提交。

4. 已配置时重新进入执行，核对范围并确认。

   ```sh
   npm run blog -- sync
   ```

   核对并确认后备份，不改变公开网站。

5. 等待独立 .blog/git-content checkout 提交与推送，以及未同步发布记录补记。

6. 检查同步结果；多设备冲突时停下核对远端，不强推覆盖。

### sync 实际备份哪些东西

它复制整个本地 content 树，包括未发布文章、未引用附件和旧样例；还保存正文模板、内容时区配置，并补记已有发布回执。公开包只包含明确选择的内容，sync 则不能按“只公开了 B，所以只备份 B”理解。

网站页面代码、头像、公开个人资料配置不由这个内容备份替代；`.blog-store/` 的冻结代码、完整发布包与 Pages 状态也不是把整个目录原样上传。重要数据仍须另做私有备份，尤其 Pages-only 不能靠公开网页恢复持久存储。

### 读懂备份计划

`added` 是上次备份后新增文件，`modified` 是字节变化的文件，`deleted` 是本地已经移除的文件；执行会让内容分支反映这些本地变化，删除的备份文件仍可能存在 Git 历史中。`warnings` 中的大文件要主动核对，默认上限为单个源文件 100 MiB，不会自动启用 LFS。

执行期间不要继续改写备份范围文件；确认后字节变化会拒绝覆盖。看到 SYNCED 后去 Git 服务核对 content-source 分支中的 content，而不是在 main 或公开 blog 分支寻找草稿。

## 确认结果

没有 Git 时 SKIPPED；配置后有实际 Git 备份结果。服务器公开集合完全不改变。

## 影响与取消

使用独立内容 checkout，不改根项目 index、不 stash/reset 用户工作区；上传前关闭隔离仓库 hooks。

## 常见问题

visibility=unconfirmed 禁止上传。源文件过大先处理，不自动启用 LFS。

- 不再想备份某个未引用附件：先在自己的本地写作中决定是否移走它，再查看 sync 计划；未引用并不等于不备份。
- 秘密文件被阻止：不要改扩展名绕过检查；即使普通 txt / json 能备份，也要人工检查敏感信息。
- 多设备出现新远端提交：先 restore 到新目录并比较两边文章 / 素材，明确合并方案；CLI 不自动合并，不删除 `.blog-store/git.json` 或 pending 回执来假装首次同步。
