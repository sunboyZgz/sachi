# 从服务器恢复公开内容

## 什么时候用

只有服务器上的当前公开版本可用时使用。恢复可校验的公开原稿与快照，不能找回从未上传的草稿。

## 开始前

部署已配置，服务器有当前成功公开版本。准备尚不存在的新目录。

本页仅适用于 deploy 的 SSH 或本地验收部署器。Pages 没有服务器私有发布包，当前 recover 不支持从 Pages URL / blog 分支自动恢复。Pages-only 请保护原工作区与 `.blog-store/`，有独立 Git 内容备份时使用 restore。

## 操作步骤

1. 先核实服务器当前 release-id。

2. 进入“从服务器恢复公开内容 · recover”，输入新的绝对目录。

3. 先看计划，核对来源版本与目的目录。

4. 重新进入执行并确认，下载私有包并验证校验摘要。

5. 检查恢复的 Markdown、引用原素材、轮廓和媒体配置。

6. 冻结网站代码和文章快照补齐到本项目 .blog-store，下载与校验中间包位于 .blog/recovery；不是把网站源代码写进新文章目录，也不是把整个持久存储恢复成原电脑的状态。

### 恢复后应检查的目录

假设目的地是一个新的 `sachi-public-recovered`，文章仍按 `content/<栏目>/<日期>/index.md` 放在它里面，引用的原素材在同篇 assets，可选 media.yaml 也会恢复。它们来自当前公开快照，不是服务器临时导出 HTML 的反向转换。

本项目 `.blog-store/snapshots/` 与 `.blog-store/code/` 同时补齐用于保留旧修订的对象，当前清单也会更新。先核对恢复目录，再决定把原稿合并回正式 content；recover 不会自动把它们覆盖到当前写作目录，也不会把被冻结的网站源码覆盖回 src。

### 无法找回的内容

未发布草稿、未引用素材、公开后继续编辑但尚未发布的修订，不在当前服务器公开包中。旧历史版本也不是此命令的选择项；本页取当前版本。需要草稿靠独立内容备份，需要完整本机状态靠额外私有备份，不靠网页缓存。

## 确认结果

返回 RESTORED。包含服务器公开快照，不包含未备份、未公开草稿。

## 影响与取消

更新本项目持久快照与清单，但不会切换网站或覆盖当前原稿。

## 常见问题

不要把 .blog-store 当缓存删除。若私有包校验失败，保留现有写作并排查服务器，不从工作副本假造旧快照。

## 参数方式

尖括号是占位符，应换成实际文章或目录，不要原样执行。未安装简短命令时用 `npm run blog --`；已安装时可替换成 `blog`。

```sh
npm run blog -- recover --destination <尚不存在的新目录> --dry-run
npm run blog -- recover --destination <尚不存在的新目录> --yes
```
