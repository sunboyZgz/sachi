# Yandu 通用媒体验收目标

这是一份可独立交给 Yandu 项目实施的验收目标。本页保留早期通用媒体处理的验收目标，不能作为最新服务端能力清单。Sachi 已有 Yandu 存储适配和最终产物上传，现状与部署结果见[实际验收记录](/reference/yandu-deployment)。作品登记仍保持待媒体处理，本页不代表其自动发布流程已完成。Yandu 的约束、接口和结果必须适用于任意业务项目，不能加入作品名称、舞台字段、Sachi 专用预设或固定 10 MB 的全局规则。

## 已有能力与待实现能力

截至本次对本地 Yandu v0.2 源码及 OpenAPI 的核对：

| 能力 | 当前情况 | 本次验收要求 |
| --- | --- | --- |
| 项目凭证和权限隔离 | 已有 Bearer 项目凭证及操作权限 | 延续隔离，约束不能提升权限或绕过配额 |
| 上传意图、幂等键、Tus 续传 | 已有；只有 READY 表示原件入库成功 | 保留原行为，原件就绪不能冒充媒体任务成功 |
| 媒体预设 | 已有 thumbnail、WebP、视频封面、MP4 720、HLS 720 预设 | 复用通用预设，能力发现明确列出各自支持的约束 |
| 异步处理及派生物 | 已有任务队列、受鉴权派生物、metadata.json | 增加绑定明确源版本的、可单独查询的处理结果 |
| 输出大小预算 | 当前有内部工作目录／产物空间预算 | 与调用方请求的单文件字节上限分别校验，不能互相替代 |
| 请求级单文件上限与超限策略 | 当前契约未提供 | 新增可发现、可验证的通用约束 |
| 超限保留开头、裁掉尾部 | 当前未提供 | 经调用方事先授权后生成新的完整可播放产物 |
| 标准结果摘要与裁剪时长 | 当前契约未完整提供 | 返回本页规定的真实结果，调用方可独立核对 |

这些是接口与实现现状核对，不能作为真实部署、跨平台工具链或性能验收结果。Yandu 后续实施仍需更新 OpenAPI、生成 SDK、服务实现、文档和真实媒体测试。

## 通用请求约束

约束由调用方按任务提供。服务端根据项目权限、配额、支持格式和资源预算决定是否接受，不能仅因为请求带了参数就扩大允许范围。

建议在现有媒体任务契约中增加以下可选结构；下面是**待实现的建议契约**，不是当前可调用接口：

```http
POST /storage/v1/projects/{projectId}/jobs
Authorization: Bearer <项目凭证>
Idempotency-Key: <逻辑任务的唯一键>
Content-Type: application/json
```

```json
{
  "objectId": "待处理对象ID",
  "expectedVersionId": "已确认的源版本ID",
  "presets": ["mp4-720-v1"],
  "outputConstraints": {
    "mp4-720-v1": {
      "maxFileBytes": 10000000,
      "onOverflow": "keep-start"
    }
  }
}
```

`maxFileBytes` 必须为服务端允许范围内的安全正整数，单位是字节，包含媒体容器头、索引、音视频和其他最终文件内容。只限制明确的目标媒体文件，不把 metadata.json、封面或全部工作目录大小算成同一个视频文件。多产物预设必须在契约中明确目标；不支持该约束的格式或预设应拒绝，不能猜测。

两种通用策略：

| 策略 | 服务行为 | Sachi 当前保存的未来策略 |
| --- | --- | --- |
| reject | 完整压缩结果超限则任务失败，不裁剪 | reject |
| keep-start | 完整结果超限时，允许保留开头、删除尾部 | trim-start |

Sachi 的 `trim-start` 表示**保留开头**；这只是调用方字段，与服务端通用枚举通过适配映射。其他项目可请求 2,000,000、20,000,000 等允许的上限。10,000,000 是一项业务约束，不进入 Yandu 的全局固定逻辑。

调用方在首次提交前取得授权，再随任务请求发送策略。服务端处理时不回调人工确认。未提供策略不能静默裁剪；未提供新约束继续保持原有预设行为。

## 能力发现与提交状态

现有 `/capabilities` 应扩展通用输出约束声明，例如：

```json
{
  "mediaReady": true,
  "presets": ["mp4-720-v1"],
  "outputConstraintCapabilities": {
    "version": 1,
    "presets": {
      "mp4-720-v1": {
        "supportsMaxFileBytes": true,
        "overflowPolicies": ["reject", "keep-start"],
        "maxAllowedFileBytes": 20000000
      }
    }
  }
}
```

示例数值仅表示结构，实际允许值由服务端管理。能力声明缺失、组件未就绪、不支持所选策略或请求超出允许范围时，在任务提交阶段明确拒绝；不能丢弃未知约束后返回旧行为的成功结果。

提交返回任务 ID 和绑定的源版本。提供按任务 ID 查询的稳定入口，不要求业务依靠“最近 100 个任务”推测结果。查询分别表示排队、运行、成功、失败和取消；原件 READY、Tus 字节完成、HTTP 请求成功都不等于处理完成。

## 处理及结果完整性

处理顺序为：验证源版本与请求 → 按现有预设完整压缩 → 核对真实文件大小 → 必要且已授权时裁剪 → 核对最终大小和播放完整性 → 入库并提交结果。

- 完整结果不超限，保留完整时长，标记未裁剪。
- 完整结果超限且策略为 reject，任务失败，返回实测大小和限制；不生成“成功但超限”的结果。
- 已授权时沿媒体时间线裁剪，并重新生成完整容器；不能按原文件字节直接截断。不要求恰好填满上限，但产物必须大于零、大小不超限、画面可播放、有合法时长且音画同步。
- 不能保留有效可播放片段时失败，不能伪造空产物、零时长或删除所有画面来满足大小要求。
- 原件保持完整；裁剪产物单独保存。源对象替换或删除后，不得把旧任务产物错误关联到新版本。

成功结果应至少提供以下字段。示例为说明结构的建议响应，实际数字必须从产物取得：

```json
{
  "id": "任务ID",
  "state": "succeeded",
  "objectId": "源对象ID",
  "sourceVersionId": "源版本ID",
  "sourceSha256": "实际源文件SHA256",
  "preset": "mp4-720-v1",
  "processingVersion": "实际处理流水线版本",
  "appliedConstraints": {
    "maxFileBytes": 10000000,
    "onOverflow": "keep-start"
  },
  "result": {
    "derivativeId": "可读取的派生物ID",
    "originalDurationSeconds": 120,
    "fullCompressedBytes": 15000000,
    "outputDurationSeconds": 78.4,
    "outputBytes": 9780000,
    "outputSha256": "实际产物SHA256",
    "mime": "video/mp4",
    "trimmed": true,
    "retainedRange": { "startSeconds": 0, "endSeconds": 78.4 }
  }
}
```

保留秒数必须通过最终产物重新探测，不能由原大小、平均码率或比例推算充当实际结果。产物字节数、SHA256、类型和时长要与下载得到的文件一致。调用方可以据此检查上限、显示删掉多少秒并冻结产物，无需获得压缩内部算法。

失败结果应明确原因及已知的实测值，例如：

```json
{
  "id": "任务ID",
  "state": "failed",
  "error": {
    "code": "OUTPUT_LIMIT_EXCEEDED",
    "message": "Full output exceeds the requested file limit",
    "details": { "maxFileBytes": 10000000, "fullCompressedBytes": 15000000 }
  }
}
```

错误码至少区分不支持的约束、缺少授权、超限拒绝、无法生成有效裁剪产物、源版本变化、处理失败和权限／空间问题。未取得的实际结果使用缺省或 null，不能填零或估算成功值。

## 幂等、并发与权限

- 同一个逻辑任务的重试保留幂等键；同键不同源版本、预设、输出约束或策略返回冲突。
- 任务去重键包含对象、源版本、处理流水线版本、完整约束和策略，不能仅按旧的“版本 + 预设”复用忽略新约束的结果。
- 上传、处理、查询和下载保持原项目隔离；绑定源版本，提交产物时再次检查对象、凭证、项目状态及可用空间。
- 网络响应丢失后先查已有任务；恢复状态不得重复裁剪或发布未经校验的候选产物。
- 处理失败、用户取消及断点恢复保留可追踪状态，候选文件和空间预留按现有持久清理机制回收，不误删原件。

## 真实验收清单

使用不同大小、时长、码率、关键帧分布及有声／无声的真实可解码视频。必须下载产物后通过独立工具核对字节数、SHA256、时长和解码，并在浏览器播放；模拟 HTTP 成功或填写假的任务响应不算通过。

| 场景 | 通过标准 |
| --- | --- |
| 多业务、多上限 | 两个独立项目分别使用 2 MB、10 MB、20 MB 的允许参数，结果互不影响 |
| 未请求约束 | 旧客户端的原预设行为与返回兼容，不自动裁剪 |
| 缺失／不支持能力 | 新调用在处理提交前明确失败，不忽略约束 |
| 等于上限 | 真实最终文件恰好上限时成功；不按 MiB 偷换单位 |
| 超限且拒绝 | 一字节超限也不能成功；原件仍可完整读取 |
| 授权保留开头 | 最终产物可播放、不超过上限，起点为零，尾部裁掉，原件摘要不变 |
| 完整结果合格 | 即使允许裁剪也不裁剪；保留完整内容 |
| 变码率视频 | 使用最终产物的实测值，不用平均码率估计冒充大小或时长 |
| 容器与音轨 | 大索引、音轨、关键帧边界均计入大小，裁剪结果音画同步 |
| 无有效片段 | 明确失败，不输出空文件或无法播放的成功结果 |
| 任务重试／续传 | 重试不产生重复对象或不同结果，提交响应丢失后能查询原任务 |
| 参数改变 | 同键不同参数冲突；不同上限／策略不能复用不满足约束的旧结果 |
| 并发替换／删除 | 旧源版本任务不能错误成为新版本的可用结果 |
| 项目与凭证隔离 | 另一项目无法查任务、读原件或产物；撤销凭证后不能继续提交 |
| 资源故障 | 配额不足、组件故障、磁盘空间不足或处理中断有明确结果及可核对的清理记录 |

验收报告记录服务版本、OpenAPI／SDK 版本、组件版本、测试平台、素材摘要、请求约束、任务 ID、源版本、最终产物摘要和实测结果。仍未执行的项明确标注，不以单个平台或样例替代其他平台的验收。

## 与当前 CLI 的衔接边界

目前 [toy 命令](/reference/commands/toy)仅保存 `pending-media` 资料、原文件引用／摘要和前置策略；没有上传、处理、裁剪、舞台读取或作品发布入口。未来接入前，先完成上述通用能力验收，再实现调用方适配、结果下载和独立校验。

作品必填字段和 10 MB 业务规则留在 Sachi；Yandu 只负责通用文件、版本、处理约束与真实产物。这份文档不要求在本次 CLI 工作中更改 Yandu 代码。
