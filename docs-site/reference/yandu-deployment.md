## 已交付的实现

- CLI 原配置向导增加 Yandu 项目绑定；新增 `storage` 初始化、状态、私有同步、检查点恢复、头像和按 ID 上传操作。
- 可重复的目录初始化、持久上传意图、Tus 偏移续传、独立本地原件保护、READY 后流式回读校验。
- 个人头像使用可选个人资料资源引用，保持原头部/半身用途；原文件及旧资料留存。
- 文章仍用本地 `./assets/` 写作，最终展示产物上传到按文章 ID 的目录；新发布冻结项目、对象、版本、摘要、类型和大小。旧快照不补默认字段、不重算历史摘要。
- 发布包提供私有精确资源授权表；静态产物没有项目密钥。代理只读当前已激活清单，不扫描未发布包。
- 独立 Node 资源代理、systemd 单元、HTTPS Nginx 和私密 JSON 配置模板；可独立部署，无开发电脑绝对路径或相邻源码依赖。
- 公开媒体服务端磁盘缓存容量为 0；新请求先授权，响应 no-cache；隧道或凭证异常会返回失败，正文仍可阅读。

部署操作见[服务器步骤](/setup/server)，私有迁移和恢复见[Yandu 接入](/setup/yandu)。代理程序、精确安装命令和模板在项目 `tools/resource-proxy/README.md` 与 `deploy/`。

## 回滚与资料保留

- 站点使用原 `blog rollback --to <release-id>`，静态页面和资源清单一起原子切换；本地原稿不回退。
- 当前版本撤回文章时，其历史资源匿名入口一并撤销；回滚恢复目标发布版本的授权集合。
- 所有被保留发布版本引用的 Yandu 对象与原件版本都需保留；不执行自动云端清理。
- 迁移确认前保留本地原件、旧头像、保护副本和迁移日志；恢复只写新目录，失败保留不完整标记。
- 服务升级保留旧代理程序和服务配置，失败时恢复并重启；不以开放目录方式绕过故障。
