# 配置个人信息

## 什么时候用

修改站名、签名、简介、封面小标、版权年份，以及关于我页面的详细介绍、兴趣、近况和公开链接。首页、关于我、共享页头、文章末尾署名、页脚和 SEO 共用同一份配置，不需要逐页修改。

## 开始前

在项目根目录找到 `src/config/profile.json`。这是公开资料配置，不放密码、私有联系方式、Git 地址或服务器密钥。部署配置仍放在 `blog.config.json`。

## 操作步骤

1. 用编辑器打开 `src/config/profile.json`，保留 JSON 的引号、逗号和字段名。

2. 修改 `name`（站名兼作者名）、`signature`（签名）、`bio`（个人简介）和 `homeLabel`（首页小标）。默认内容与现有设计一致，不需要替换也可原样保留。

   ### 完整配置长什么样

   下面是与默认站点一致的完整结构。修改自己的值即可，不增加第二份个人信息文件：

   ```json
   {
     "name": "请叫我木头人",
     "signature": "吾生君未生，君生吾已老",
     "bio": "双鱼·INFJ·生活第一，工作第二·想要成为有趣的人。",
     "homeLabel": "个人手记",
     "copyrightStartYear": 2026,
     "authorUrl": null,
     "sameAs": [],
     "about": {
       "introduction": [],
       "interests": [],
       "updates": [],
       "links": []
     },
     "seo": {
       "description": null,
       "allowIndexing": true
     }
   }
   ```

   JSON 不允许注释或最后一个字段后的多余逗号。`null`、`true` 和年份不加字符串引号；sameAs 是数组，不是一段逗号分隔文字。

   | 字段 | 显示 / 使用位置 | 校验边界 |
   | --- | --- | --- |
   | name | 首页、站名、署名、页脚与 SEO 作者 | 非空，最多 100 字符 |
   | signature | 首页和关于我页面的签名 | 非空，最多 200 字符 |
   | bio | 首页与关于我页面的简介、文末署名、默认 SEO 摘要 | 非空，最多 500 字符 |
   | homeLabel | 首页小标 | 非空，最多 50 字符 |
   | copyrightStartYear | 页脚年份 | 整数，1900–9999 |
   | authorUrl / sameAs | 公开作者资料与结构化数据 | HTTP(S)，不含登录信息；sameAs 最多 10 项 |
   | about | 关于我页面的扩展介绍、兴趣、近况与公开链接 | 可省略；内部字段见下方说明 |
   | seo.description | 全站摘要覆盖 | null 或非空文本，最多 300 字符 |
   | seo.allowIndexing | 正式页面的索引策略 | 布尔值；不是访问权限 |

   验收时同时看默认题字图和改名后的文字回退，以及桌面 / 手机的长简介换行。不要只在一个页面确认姓名，因为这些字段还会进入分享信息与结构化数据。

3. 把 `copyrightStartYear` 设为开始写作的四位年份。页脚会显示开始年份或开始年份至构建年份的区间。

4. 可选：把 `authorUrl` 从 `null` 改成公开的作者资料页网址；在 `sameAs` 数组中填公开主页。没有就保留 `null` 和 `[]`，不会添加关注按钮或新的常驻导航。

   关于我页面的扩展资料填写在同一文件的 `about` 对象中：

   | 字段 | 填写方式 | 页面位置 |
   | --- | --- | --- |
   | about.introduction | 字符串数组，每项是一段详细介绍 | 写在这里 |
   | about.interests | 字符串数组，每项是一条兴趣或生活习惯 | 生活里的我 |
   | about.updates | 对象数组，每项包含 text 和 date；date 使用 YYYY-MM-DD | 最近在做 |
   | about.links | 对象数组，每项包含 label 和 url；url 使用公开 HTTP(S) 地址 | 公开链接 |

   数组留空时对应区域自动隐藏，不显示占位文案。近况由作者维护，与自动生成的文章记录分别存储。旧配置省略 `about` 时自动使用空资料，不影响原有身份字段。

5. 可选：填写 `seo.description` 作为全站摘要。保留 `null` 会自动使用 `bio`。文章仍优先使用自己的 `summary`，没有时从正文提取摘要。

6. 用 `npm run dev` 预览首页、关于我、目录和文章末尾署名。保存配置后，本地预览会自动更新。默认站名和签名使用已有题字图；修改文字后自动显示真实文字，不继续显示旧 SVG 里的题字。若需要新书法题字，另行更新对应 SVG 及 `src/config/profile.ts` 中的素材文字描述。

   ```sh
   npm run dev
   ```

   在 4173 预览本地身份信息。

7. 运行 `npm run check`。确认显示正确后，再按[全站基线变更](/release/baseline)进行构建和发布。无正式文章时，`npm run build` 只生成空站，不会把样例文章发布。

   ```sh
   npm run check
   ```

   通过后按照全站基线流程明确发布。

## 确认结果

所有页面和分享信息中的作者名一致，页脚不再单独写死姓名。改名后的首页可直接看到新文字，而不仅是屏幕阅读器读到新名字。关于我页面展示填写后的资料，空数组对应的区域保持隐藏。

### 自动生成的文章数据

写作日历不需要配置篇数或日期。页面自动从当前公开发布清单中读取文章的首次发布时间、标题、栏目与链接，按博客时区生成热点图、本年发布篇数、发文天数和当天文章列表。

每次正式发布后，这些数据随静态站重新生成。新增文章增加对应日期的记录；修改既有文章或重复部署不增加首次发文数量；撤回文章后，它会从当前公开统计中移除，再次公开时沿用原首次发布日期。

日常预览读取本地已有的公开清单，不将未发布草稿算入统计；没有公开发布记录时显示零。独立 fixture 预览用于排版测试，不代表真实发文。数据源是博客自身的发布记录，不需要连接 GitHub，也不使用 Git 提交次数。

## 影响与取消

配置属于全站代码基线，会改变代码哈希，需要明确接受全站基线变化。冻结计划、旧发布包和回滚保留当时的配置，不混入后续修改。执行前恢复配置可取消本地变化。

头像仍只覆盖 `src/assets/avatar/avatar-head.png` 和 `avatar-half.png`，见[替换头像](/writing/avatar)。不要在本配置或文章中复制头像。

## 常见问题

- JSON 报错：检查逗号、引号和字段拼写；不接受未知字段。
- 修改后线上未变：保存不是发布，必须构建并明确发布新基线。
- 两幅题字图没同步：文字变更自动降级为文字排版；只有制作了对应的新图后才改素材描述。
- 栏目怎么改：三个栏目是内容路径与页面的固定契约，不属于个人信息配置，不擅自重命名。
- 日历为什么是零：只有正式发布的文章才进入发文统计，新建或保存草稿不会产生发文记录。
