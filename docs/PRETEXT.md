# Markdown 与 Pretext 的职责边界

当前站点直接依赖 `@chenglou/pretext@0.0.9`，不再复制包文件，也不再把 Canvas 近似实现当作运行引擎。

## 数据流

1. 构建期读取 Markdown 和 frontmatter，并用 Zod 校验元数据。
2. Markdown 解析为 AST；标题生成文章目录和稳定锚点。
3. 有 `flow` 配置时，按配置独立图片及其相邻连续纯文本识别有序环绕区域，不依赖标题。
4. 其余标题、段落、引用、列表、代码和表格交给标准 Markdown/GFM 渲染。
5. 浏览器端 `FlowParagraphs` 使用 Pretext 预计算文本并根据透明轮廓生成可用行段；视觉行是 DOM 文本，不绘制到 Canvas。

环绕区域只能包含纯文本段落和一张图片。链接、强调、行内代码或其他富文本是边界，继续交给普通 Markdown；连续候选区出现多张配置图片时必须以普通块分隔。

## 交互与降级

桌面宽度达到 520px 时启用环绕。读者可主动开启拖动，用方向键每次移动 12px、还原位置或切到普通排版。手机、打印、Pretext 异常、轮廓文件异常都会保留完整 DOM 正文并使用普通图文版式。

`data-engine="pretext"` 表示真实包已运行；`data-engine="plain-dom"` 表示普通排版或降级，状态说明具体原因。浏览器测试必须实际断言前者，不能只用几何单元测试替代。

若更换图片裁切、透明边缘或尺寸，必须重新生成轮廓，并同时更新 frontmatter、素材清单和回归测试。

`FlowConfig = FlowSpec | FlowSpec[]` 保持原单图对象形态。完整 AST 先分析标题和源位置，再替换识别出的局部块；不切片重解析 Markdown。配置保留原资源路径，展示 URL 只在渲染层映射，多个媒体及轮廓分别冻结。width 控制完整画布宽度，不限高、不裁切，手机、打印与普通图文采用同一尺寸。

## 读者位置记忆

网站按文章 ID 与区域标识分别记录 localStorage 阅读偏好。拖动结束（包括失去指针捕获）和方向键移动后保存；不会在每个拖动帧或自动重排时写入。横坐标保存为可移动宽度内的比例，纵坐标保存为区域内像素，首次环绕排版前恢复。调整窗口、移动端降级、打印和字体重排保留同一偏好。

图片 URL／轮廓版本、有效宽度或默认位置改变会使旧记录失效；正文编辑不清除偏好。“还原位置”只清除当前区域记录。无效记录、存储权限和配额异常静默退回可用的默认排版，SSR 不访问浏览器存储。未启用源码定位且传入文章标识的阅读组件才保存位置；插件写作预览与教学示例保持临时互动。
